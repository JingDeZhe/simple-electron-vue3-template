# 🧩 项目开发规范（请严格遵守）

1. **包管理器**
   - 必须使用 `pnpm` 安装依赖和运行脚本。
   - **禁止使用 `npm`、`yarn` 或其他包管理器**。

2. **图标使用**
   - 所有图标必须通过 `<i class="i-tabler-xxx" />` 引入，基于 `unocss` + `@iconify/json` 的 Tabler 图标集。
   - **不得内联 SVG 或引入其他图标库**。

3. **共享代码组织**
   - 前后端共用的逻辑、工具函数、常量等，统一放在 `src/shared/` 目录下。
   - 在 `main`、`renderer`、`preload` 等所有上下文中，**必须通过 `@shared/...` 路径别名引用**，例如：
     ```ts
     import { getUid, toDeepRaw } from '@shared/utils'
     ```

4. **类型定义复用**
   - 所有公共 TypeScript 类型（接口、枚举、联合类型等）**必须集中定义在 `src/shared/type.ts`**。
   - **严禁在其他文件中重复或近似定义已有类型**，确保全项目类型一致性。

5. **API 参数处理**
   - 前端调用后端 API 时，若参数包含 Vue 响应式对象（如 `ref`、`reactive`），**必须用 `toDeepRaw()` 包装后再传递**，避免 Proxy 对象因无法序列化或结构克隆失败导致错误：
     ```ts
     api.fetchData(toDeepRaw(params))
     ```

6. **代码注释原则**
   - **只写必要注释**：解释“为什么这么做”，而非“做了什么”。
   - 逻辑清晰、自解释的代码（如简单赋值、标准流程）**无需注释**。
   - **禁止冗余、过时或显而易见的注释**（如 `// 定义变量 x`）。

7. **UI 与布局**
   - **优先使用 `unocss` 工具类实现布局与间距**，减少对 `naive-ui` 中基础容器组件（如 `n-flex`、`n-space`、`n-list`）的依赖。
   - **滚动区域应限定在内容区块内部**（例如通过 `flex-1 overflow-auto` 实现），**禁止在页面最外层（如 `body` 或根容器）出现滚动条**，确保整体布局符合嵌套滚动预期。
